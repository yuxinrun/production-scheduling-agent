# 拉格朗日松弛与对偶定理

如果排产里只留一个数学定理，应该是这一条：

> **弱对偶定理**：对最小化问题，拉格朗日对偶函数的**任何**取值，都不会超过原问题的最优值。
> 也就是说 `θ(λ) ≤ z*` 对一切 `λ ≥ 0` 成立。

它的工程含义粗暴且值钱：**你不必算出最优解，就能知道最优解至少有多好。**
上一节说「报告 gap 而不是报告最优」，gap 的分母来自可行解，分子就是这条定理给的。
没有它，你所有的「这个方案比人工好 12%」都是空口白话。

---

## 一、什么时候该用它

排产模型的约束分两类：

- **容易的**：一道工序的内部逻辑、单工件的工艺路线、单机排序——这些子问题能秒解。
- **讨厌的**：把不同工件**耦合**起来的约束——「这台机器同时只能干一件」「全厂这个月只有 640 机时」「这批料只能供 3 张工单」。

拉格朗日松弛的适用条件非常明确：**把讨厌的约束移进目标函数后，剩下的问题能按工件/按机器完全分解。**

```text
原问题 (P)   min  f(x)          s.t.  g(x) ≤ b,  x ∈ X
                                    ↑ 这条（或这几条）就是「耦合约束」

拉格朗日松弛  L(λ) = min  f(x) + λᵀ (g(x) − b)   s.t.  x ∈ X
                                ↑ 惩罚项                    ↑ 容易的约束留在里面
```

`x ∈ X` 必须是一个**能高效求解**的集合。对排产，X 通常意味着「每个工件独立走自己的工艺路线」，
于是 `L(λ)` 拆成 `|J|` 个互不相干的小问题，每个都能瞬间解完——
**这才是拉格朗日松弛的全部吸引力：它不是求解器，是分解器。**

::: tip 一个具体的分解
「每台设备的可用机时 ≤ T」这条约束把不同工件绑在一起（工件 A 占了 3 小时，B 就少 3 小时）。
松弛掉它之后，每个工件独立地问：**在哪台设备上、按这个 λ 定价，我的「成本 + 占用租金」最低？**
`L(λ)` 立刻变成 `|J|` 个「枚举候选机器取最小」的循环。6 个工件 2 台设备，一毫秒出结果。
下面的交互图就是这个例子，你可以自己点。
:::

看这张图时注意四件事：

1. **青色线（下界 θ）永远压在红色线（穷举出来的真最优 z\*）下面。** 这不是算法没收敛，这是定理。
   蓝色线（修复后可行解的上界 U）则永远在上面。真最优被夹在中间，而夹住它的两条线你都算得出来。
2. **青色线是锯齿状的。** 次梯度法不保证单调——对偶函数是凹的分段线性，
   步长太大就会跨过拐点。所以图里同时画了「原始采样」（灰色虚线，抖得厉害）和「历史最好值」（青色，只升不降）。
   你的日志里看到「对偶值反而变差了」是正常的，别当 bug 修，**报告 best-so-far**。
3. **间隙 `U − θ` 在这个例子里只有 0.3 ~ 0.8**（成本单位），把 T 从 8 拖到 16 会看到它一路缩到 0。
   产能紧 → 冲突强 → 间隙大；产能松到不构成约束 → 两侧吻合，间隙归零。
   **这条趋势比间隙的绝对值重要**：它告诉你哪条约束值得再花算力去收紧。
4. **θ 与 U 不重合的那段距离 = 整数间隙。** 它不会靠「再多算一会儿」自动消失，
   要么加割、要么分支、要么换更强的松弛。

## 三、弱对偶定理：为什么 λ 再乱也给下界

这条证明只有三行，值得背下来——它是你说服计划员「我的数字不是拍脑袋」的全部武器。

<details>
<summary>展开证明（最小化问题）</summary>

设 `x*` 是原问题 (P) 的最优解，`X` 是松弛后可行域，所以 `(P)` 的可行集 `⊆ X`，且 `x* ∈ X`（因为它满足 `X` 里那些约束）。

对任意 `λ ≥ 0`：

```text
z*  =  f(x*)                                  # 定义
    ≥  f(x*) + λᵀ(g(x*) − b)                  # 因为 g(x*) ≤ b 且 λ ≥ 0 ⇒ λᵀ(g(x*)−b) ≤ 0
    ≥  min_{x ∈ X} [ f(x) + λᵀ(g(x) − b) ]    # 因为 x* ∈ X，最小值不会比在 x* 处更大
    =  θ(λ)
```

∎ 所以 `θ(λ) ≤ z*` 对**所有** `λ ≥ 0` 成立。最好的那个是 `max_{λ≥0} θ(λ)`，即**拉格朗日对偶问题 (D)**。

关键推论：**你不需要收敛，你已经有了一个界。** 迭代到第 7 步的 `θ(λ⁽⁷⁾)` 也是一条合法的下界。
这跟梯度下降在深度学习里「没收敛就没意义」完全不同——这是许多人第一次接触对偶时的认知断层。

</details>

对应的另一半：**弱对偶的互补松紧**。若 `θ(λ*) < z*`，说明存在**整数间隙**，
此时任何算法都不会自动帮你闭合它，只能靠加割、靠分支、靠更强的松弛（`Lagrangian deep relaxation`，Caprara 等 1999）。

**LP 对偶取等，MILP 不一定取等。** 线性规划里 `z_LP = θ_LP`（强对偶），
但整数规划里 `z_IP ≤ θ_LR ≤ z_LP ≤ …`，这条链上的每一环都可能是松的。
你看到的 gap 是这几层的总和。

## 四、次梯度算法：唯一你要写的循环

```text
λ⁽⁰⁾ = 0，k = 0
重复：
  1. 解子问题  x⁽ᵏ⁾ ∈ argmin_{x∈X} [ f(x) + λ⁽ᵏ⁾ᵀ(g(x) − b) ]
  2. 算次梯度  s⁽ᵏ⁾ = g(x⁽ᵏ⁾) − b          # 违反了就 > 0，闲着就 < 0
  3. 若所有 s⁽ᵏ⁾ ≤ 0 且目标已收敛 → 停
  4. 更新      λ⁽ᵏ⁺¹⁾ = max(0, λ⁽ᵏ⁾ + t⁽ᵏ⁾ · s⁽ᵏ⁾)
  5. k += 1
```

`s = g(x) − b` 的直觉就是「这台设备超载 3.5 小时」——
**次梯度不是导数，它就直接是违反量。** 这也是它能写成一个 for 循环的原因。

### 步长怎么选（这里是全部技术含量）

| 步长规则 | 公式 | 特点 |
| --- | --- | --- |
| **Polyak（1964）** | `t = β (z_ub − θ(λ)) / ‖s‖²` | 需要**已知的上界** `z_ub`（来自某个可行解）。收敛快，最常用 |
| 调和递减 | `t = α / k` | 理论漂亮，实践慢得像退休 |
| 几何衰减 | `t = α · σᵏ, σ≈0.9~0.95` | 无脑可用，需要调 `α` |
| Held–Karp（1971） | 实践中「无改进就减半」 | TSP 下界的传奇；简单、稳，本手册的交互图用的是它 + Polyak 混合 |

::: warning 一个会把你送进 ICU 的实现细节
Polyak 步长的分母是 `‖s‖²`。当所有约束都不违反时 `s = 0`，
**除以零 → λ 变成 NaN → 整个模型崩**。别笑，这是拉格朗日实现里第一大 bug。
本手册的交互组件里就有这一段：`norm2 < 1e-12` 直接停止迭代。
另一半是 `z_ub = +∞`（还没拿到可行解）时 Polyak 步长也是无穷——必须先退化成别的规则。
:::

### 停止条件（三个，任一个满足就停）

1. `s ≤ 0`（无违反）且 `θ(λ)` 与目标已知的最好可行解足够接近；
2. 连续 N 次步长减半后仍无改进（典型 N = 5~20）；
3. 迭代预算或时间预算用完。**真实项目里 99% 走这一条。**

## 五、λ 是什么：设备的影子价格

这是拉格朗日松弛在现场最有说服力的输出，比解本身还有价值。

- `λ_k` 大 → 资源 `k` 超载、所有人都在抢 → **它就是瓶颈**。
- `λ_k = 0` → 这条约束在最优处没咬住 → 加更多产能**不改善目标**（互补松紧）。
- 「约束右端 +1 单位，目标改善多少」= **影子价格**。只在当前基附近有效，跨拐点即失效。

::: tip 把 λ 显示在驾驶舱上
LISA 那类项目里，计划员真正想看的不是甘特，是这一句：
**「今天的热处理炉租金是 41.7 单位/小时，五轴是 3.2。**」
这一句话同时解释了为什么某个急件要排队、为什么插单的成本这么高。
对偶乘子是把「数学优化」翻译成「车间语言」最便宜的一座桥。
:::

互补松紧还给了你一个**免费的约束审计**：跑完之后，所有 `λ = 0` 的硬约束挑出来看一眼——
里面很可能藏着「这条约束其实根本不需要」（可以删，模型更快），
或者「这条约束被我写成软的了，所以从来没咬住过」（可能是错误）。

## 六、光有下界没用：拉格朗日启发式

`x⁽ᵏ⁾` 是松弛问题的解，**通常违反原来的耦合约束**（三张工单都选了同一台五轴）。
下界已经有了，上界还得靠修。这就是「原始解重构」（primal repair）：

```text
每轮松弛求解后：
  1. 用违反量找出超载资源上的候选集合
  2. 按「单位机时的代价增量」升序，把最便宜的工件搬去次优机器 / 推迟
  3. 搬完若无违反 → 得到一个可行解 → 更新上界 z_ub
  4. 上界变好 → Polyak 步长自动收紧 → 下一轮更准
```

这一步的顺序很关键：**上界的质量直接决定下界的收敛速度**（Polyak 里 `z_ub` 在分子上）。
一个烂的启发式会让整个拉格朗日循环在原地抖动。
所以真实系统里，`repair` 通常直接复用调度规则（SPT / EDD / CR）而不是另写一套逻辑。
试试 [派工规则实验室](/problem/heuristic) 里那几个规则，它们就是最便宜的 repair。

## 七、这套数学今天还剩多少活？

诚实的回答：**在中等规模的整数规划主战场，纯拉格朗日松弛的位置被 LP/IP 内点法 + 割平面 + 分支定界抢走了一半，被 CP 抢走了另一半。** 原因很直白：单核的拉格朗日循环打不过并行分支定界。

但四个位置它至今无可替代：

| 位置 | 为什么是它 | 排产里的样子 |
| --- | --- | --- |
| **大规模可分解** | 变量/约束按工件分解后，`|J|` 个子问题可以并行、可以分布式、可以边算边停 | 多工厂订单分配、上千张工单 + 跨厂区共享产能 |
| **只要下界** | 三行代码就有一个合法界，不需要建完整 MILP | 给「人工计划到底浪费了多少产能」一个量化答案 |
| **约束太软写不进 MILP** | 惩罚项天然处理「尽量」类约束 | 「尽量不满炉」「尽量少加班」 |
| **需要价格信号** | 唯一能直接输出影子价格的机制 | 瓶颈定价、外协报价、加班值不值 |

现代变体（名字要认识，别当新东西）：

- **拉格朗日分解**（Guignard–Kim 1987）：同时松弛变量的耦合（`x = z` 复制变量），比只松约束分得更细。多工厂/多期问题常用。
- **Volume algorithm**（Barahona–Anbil 2000）：次梯度与内点法的杂交，**同时给出原始解**（这是它对 Lagrangian 循环的最大改进）。
- **Bundle method**（Lemaréchal、Düzekin–Fletcher）：累积历史次梯度构造模型，收敛更稳，代价是要存记忆。
- **Deep Lagrangian / surrogate 松弛**（Caprara 等 1999）：把可行域也松掉一部分来缩小整数间隙。

## 八、三十行跑一遍（下面这段是实测过的）

```python
import itertools, math

P = [[3, 5], [4, 3], [2, 4], [5, 3], [2, 4], [4, 2]]   # p[i][k]：工件 i 在机器 k 上的工时
C = [[4, 7], [5, 6], [3, 6], [6, 4], [3, 5], [5, 3]]   # c[i][k]：对应成本
n, m = len(P), 2

def relax(lam, T):
    """给定乘子，分解成 n 个独立子问题：每个工件挑「成本 + λ·工时」最便宜的机器。"""
    assign, load, dual = [], [0.0] * m, 0.0
    for i in range(n):
        costs = [C[i][k] + lam[k] * P[i][k] for k in range(m)]
        k = min(range(m), key=lambda kk: costs[kk])
        assign.append(k); load[k] += P[i][k]; dual += costs[k]
    return dual - sum(lam[k] * T for k in range(m)), load, assign      # θ(λ), 违反量, 指派

def repair(assign, load, T):
    """松弛解常常超载：把超载机器上「搬过去最便宜」的工件挪到对面，直到可行。"""
    assign, load = list(assign), list(load)
    for _ in range(200):                            # 计数器兜底：搬运可能来回反弹
        if all(lk <= T for lk in load):
            return sum(C[i][assign[i]] for i in range(n)), assign
        k = max(range(m), key=lambda kk: load[kk])
        cands = [i for i in range(n) if assign[i] == k]
        if not cands:
            return None
        j = min(cands, key=lambda i: C[i][1 - k] - C[i][k])
        assign[j] = 1 - k
        load[k] -= P[j][k]; load[1 - k] += P[j][1 - k]
    return None

def subgradient(T, iters=200):
    lam, best_dual = [0.0] * m, -math.inf
    _, load0, assign0 = relax(lam, T)
    r = repair(assign0, load0, T)                   # 第 0 轮就拿到一个可行上界
    ub = r[0] if r else sum(min(row) for row in C) + 999
    for it in range(iters):
        dual, load, assign = relax(lam, T)
        if dual > best_dual:
            best_dual = dual
            cand = repair(assign, load, T)
            if cand and cand[0] < ub:
                ub = cand[0]                        # 上界变好 → Polyak 分子变窄
        s = [load[k] - T for k in range(m)]         # 次梯度 = 违反量
        if all(si <= 1e-9 for si in s):
            break                                   # 无违反：松弛解本身已可行
        norm2 = sum(si * si for si in s)
        if norm2 < 1e-12:
            break                                   # ← 防 NaN：漏了这行必崩
        t = 2.0 * (ub - best_dual) / norm2          # Polyak 步长
        lam = [max(0.0, lam[k] + t * s[k]) for k in range(m)]
    return best_dual, ub, it

def exact(T):                                       # 2^6 = 64 种指派，穷举得起
    best = None
    for a in itertools.product(range(m), repeat=n):
        load = [0] * m
        for i, k in enumerate(a):
            load[k] += P[i][k]
        if max(load) <= T:
            best = min(best or math.inf, sum(C[i][a[i]] for i in range(n)))
    return best

print(f"{'T':>3} {'z*':>4} {'下界 LB':>9} {'上界 UB':>7} {'gap':>7} {'迭代':>4}")
for T in (8, 9, 10, 11, 13):
    lb, ub, it = subgradient(T)
    print(f"{T:>3} {exact(T):>4} {lb:>9.3f} {ub:>7} {100 * (ub - lb) / ub:>6.1f}% {it:>5}")
```

这是 Python 3.12 上的真实输出：

```text
  T   z*     下界 LB   上界 UB     gap   迭代
  8   23    22.667      23    1.4%     1
  9   23    22.400      23    2.6%     2
 10   23    22.213      23    3.4%     4
 11   22    22.000      22    0.0%     0
 13   22    22.000      22    0.0%     0
```

三件事，一件一件看：

1. **产能越紧，gap 越大**（T=11 时 0%，T=10 时 3.4%）。因为「每工件独立最优」与全局产能的冲突变强了。
   产能松到不构成约束时，两侧完全吻合——这条约束本来就不该进模型。
2. **上界恰好等于穷举出来的真最优 `z*`。** 说明这个例子里
   「松弛 + 规则修复」已经把解做对了，剩下的只有证明问题。这也是拉格朗日启发式的典型表现。
3. **迭代只用了 1~4 步。** 别误会这是算法快，是这个实例太小（`2⁶ = 64`）。
   真实项目里这个循环要跑几百到几千步，而且 **gap 不会这么乖**。

::: warning 为什么这个例子太温柔，以及真实车间哪里会变凶
本例松弛的是「机时容量」，子问题是**逐工件独立的枚举**，整数间隙很小。
换成真正的排产目标，间隙立刻变大：

- 目标是 **makespan** 而不是成本之和 → `C_max` 不可按工件分解，你只能松「机器容量」而留下排序，子问题变成一堆单机排序，界明显变松。
- 松弛的是 **`NoOverlap`**（析取约束）→ 子问题退化为「每台机器一条链」，界通常弱于 LP 松弛。
- 加上 **序列相关换型** → 独立子问题里还得解一个 TSP 式的排序，`L(λ)` 本身就不好算了。

结论：拉格朗日在排产里的甜区是**「指派类耦合」**（谁上哪台机、哪个厂做哪单、这批货走哪条线），
不是**「时序类耦合」**（同机上谁先谁后）。后者交给 CP 的推理引擎。
:::

## 九、什么时候不要用拉格朗日

- **约束本身就是一条 `NoOverlap`。** CP 的析取推理效率完胜次梯度循环，别为了炫技松它。
- **规模小**（工件 < 50）。直接 MILP/CP 求最优，还能拿到证明。拉格朗日的价值在可分解性，规模不到时那是自找麻烦。
- **你需要的是可解释性而不是速度。** 拉格朗日的解来自「松弛后的独立最优 + 修复」，
  向计划员解释「为什么这张工单被搬走了」比解释分支定界难得多。
- **上界拿不到。** Polyak 步长依赖 `z_ub`；如果你的可行解构造不出来，收敛会明显变差。
