# 现场术语速查卡

排产项目里最贵的一类 bug，不是空指针，是**两个人用同一个词说两件不同的事**。
计划员说「排产」指的是周一早上那版月计划，你说的是求解器输出的设备×时段矩阵，
MES 工程师说的是工单下达状态机——三个人点头，三行代码打架。

这张卡按**定义权**给每个词分级：谁规定它、换个厂还成立吗、写进代码时该做成常量还是配置项。
用法有三种：

1. 需求评审时当场查，别靠记忆。
2. 写数据模型前先确认词的分类（齐套九要素、指标四级这类是**表结构**，不是枚举值）。
3. 遇到本页标了 <span class="psa-chip">口径未核实</span> 的词，**必须回去问人**，不要自己发明定义。

站内搜索（`Ctrl` / `Cmd` + `K`）能直接搜到本页的表格里出现的词，比滚动快。

## 一、计划的时间层次

这一节的词长得都像同义词，实际是**五个不同的时间粒度和责任层**。你的系统只应该有一个「排产」入口，但要有五个不同的对象承接它们。

| 术语 | 英文 / 缩写 | 一句话 | 容易踩的坑 |
| --- | --- | --- | --- |
| 滚动排产 | Rolling Horizon | 每次只细算近期，远期粗略，窗口向前滚 | 「滚动」不是「每天重算一遍」：远期通常只做粗能力，重算窗口才做有限产能 |
| 周滚动 3 锁 1 下发 3 展望 | — | 一家航发厂的口径：按周滚动，锁定一段、下发一段、展望一段 <span class="psa-chip">口径未核实</span> | **原文没写单位是天还是周。** 照抄进代码前先问计划员，否则你写的锁定天数和他的差 7 倍 |
| 冻结窗口 | Time Fence / Frozen Zone | 近期计划原则上不许改 <span class="psa-chip">口径未核实</span> | 没有国标。LISA 项目自己给的定义是「周计划前 3 天锁定期」，别当成通用值 |
| 锁定期 | Frozen Bucket | 冻结窗口内，改动必须走审批 | 审批链要在求解**之前**拦，不是排完再让人否决——后者等于每天白算一遍 |
| 展望区 | Liquid / Planning Bucket | 只用来预判产能，不构成承诺 | 把展望区的数据拿去算交付承诺，客户会以为你答应了 |
| 时间围栏 | Time Fence | 冻结/半冻结/自由三个区的统称 | 围栏是**几条**不是一**个**：不同工序域可以有不同的冻结长度（试车台和五轴不一样） |
| 工单下达 | Order Release | 计划变成车间可执行的任务 | 「下达」在很多 MES 里是一次状态跃迁 + 一次库存占用，不是发个消息 |
| 转序 | Process Transfer | 一道工序做完、检验放行、进入下一道工序 <span class="psa-chip">口径未核实</span> | 行业通用但没有标准定义。真正的坑是**转序等待**：检验没放行时工件占着下道设备的产能吗？ |
| 完工报工 | Completion Report / Backflush | 现场回传「我做完了 N 件」 | LISA 现状里「完工报工月末集中」——如果你的重排依赖报工实时性，月末前你的产能账全是假的 |
| 提前期 | Lead Time / LT | 从下单到可用的时长 | 物料 LT、工序 LT、订单 LT 是三个不同的字段，混用会导致齐套结论反号 |
| 排队时间 | Queue Time | 工件在设备前等待的时间 | 离散制造里排队时间常占总制造周期 **80% 以上**，只优化加工时间的模型一定不准 |
| 在制 | WIP | 已开工未完工的数量 | WIP 是个瞬时值，快照时间点不同，同一天的数字能差一倍 |

## 二、齐套与物料

「齐套」是中文工厂语境里最被低估的概念。它是**布尔判定的集合**，不是百分比——
但所有人拿它当百分比用。写代码时你要先定：判定对象是工单、工序还是物料行？

| 术语 | 英文 / 缩写 | 一句话 | 坑 |
| --- | --- | --- | --- |
| 齐套 | Kitting / Parts Availability | 开工所需的一切都到位且有效 | 「到位」含六个维度：数量、时间、批次、效期、质量状态、归属 |
| 齐套率 | Kit Rate | 齐套的分子 ÷ 分母 | **分母决定一切。** 按工单数、按物料项、按金额算，同一个车间能给出 60%、23%、41% 三个数 |
| 齐套九要素 | — | LISA 项目的拆法：工装、主材、辅材、刀具、工艺路线、人员资质、WIP 质量状态、设备状态、设备能力 | 这不是国标，是这家厂的数据模型。**九张供给侧表**，缺表就是「未接入」而不是「不合格」 |
| 三时点齐套 | — | 排产前 / 排产后 / 开工前各查一次 | 同一条链、三个检查点，**结论可以合法地不同**。别把它做成一个缓存字段 |
| 缺项 vs 阻断 | — | 排产前只算「缺项」，落在关重件要素上的缺口在开工前判「阻断」 | 「阻断」意味着不允许开工，UI 上不能用一个黄色 warning 表示 |
| 到料 | Material Arrival | 物料实体进入厂内 | 「到料可视化」缺失是 P0 问题：你的 ETA 只能来自采购承诺，而采购承诺从来不承诺 |
| 在途 | Inbound / Open PO | 已下单未交付 | 判定规则可以很简单：**ETA 晚于开工点即判阻断**。复杂的是 ETA 本身的可信度 |
| 外协 | Subcontracting / Outsource | 工序交给厂外做 | 外协件的产能不属于你的资源池，但**交期违约的风险属于你**。要建成一条带提前期的虚拟资源 |
| 呆滞 | Slow-moving Stock | 长期不动的库存 | 它会让你的「可用量」虚高。`on_hand - allocated` 只算了一半，还要过质量状态与效期 |
| 效期 | Shelf Life | 材料/胶/涂层的可用期限 | 军品效期会**跨节假日衰减**。用自然日算，用工作日排——两个都要有 |
| BOM 展开 | BOM Explosion | 多层物料清单逐层展开需求 | 损耗率（scrap rate）在层内还是层间乘，两种实现在长流程上会指数级跑偏 |

## 三、产能、设备与负荷

| 术语 | 英文 / 缩写 | 一句话 | 坑 |
| --- | --- | --- | --- |
| 有限产能 | Finite Capacity | 一台设备同一时刻只能干一件事 | APS 的分水岭。「无限产能排产」出的计划，现场第二天就作废 |
| 粗能力核算 | RCCP | 只算关键资源够不够，不排细节 | 用来判断「这个月能不能接这单」，不能用来派工 |
| 瓶颈 | Bottleneck / Constraint | 负荷最接近或超过产能的资源 | 识别了 ≠ 管理了。LISA 原话：瓶颈「有标识未管理」，利用率只有 40~60% |
| 独生子设备 | Single-Source Machine | 全厂只有一台、坏了没处转移 | 它不是「重要设备」，是**没有替代路径**。排产里要当硬约束，不是高权重 |
| 台架 | Test Bench | 试车用的专用工位 | 台架是典型的独生子资源，窗口极窄，配不上就整条链堵死 |
| 换型 /  Setup Time | 从上一个活换到这一个活的准备时间 | **序列相关**：A→B 和 B→A 不一样。你的矩阵是对称的吗？多半不是 |
| 换型矩阵 | Sequence-dependent Setup | `setup[i][j]` 的查找表 | 现场通常只有 1/3 的格子有实测值，其余是拍的。别让求解器把拍的值当事实 |
| 组批 / 合炉 | Campaign Batching | 兼容的工件合并成一批一起处理 | 目标是**满炉率**。批内约束（材质、温度曲线、有效期）比容量更难建模 |
| 满炉率 | Furnace Loading Rate | 一炉的实际装载 ÷ 该炉最大装载 <span class="psa-chip">口径未核实</span> | 无国标公式。分母是「装具格数」「重量」还是「有效加热区体积」，三家厂三个答案 |
| 负荷率 | Utilization | 已排工时 ÷ 可用工时 | 分子里有没有排队、有没有保养？100% 负荷的系统一定天天逾期 |
| 可用时间 | Net Available Time | 日历时间扣掉保养、班制、节假日 | 跨厂区、跨节假日的日历，别只用 `weekday()` |
| OEE | Overall Equipment Effectiveness | 时间稼动率 × 净性能稼动率 × 合格率（ISO 22400-2:2014 给出定义） | 它是**事后度量**，不是排产约束。当成约束优化会得出荒谬计划 |
| 时间稼动率 | Availability | (计划运行 − 停机) ÷ 计划运行 | 停机分类（故障/换型/待料/质量）决定你重排时该改哪个参数 |
| 性能稼动率 | Performance | (理论节拍 × 数量) ÷ 实际运行时间 | 小批量多品种下这个数几乎无意义，慢件会淹没快件 |
| 计划停机 / 预防性保养 | PM | 日历上提前占掉的产能 | 必须作为**硬资源占用**入模，不是「扣一点产能」的系数 |
| 数字主线 | Digital Thread | 从设计到服务的数据贯通 | 别把它当架构名词。它是「同一件东西在全生命周期有同一个 ID」这件事 |

## 四、价值流指标与公式

这节是**能背的**。面试、评审、对齐口径都用得上。标准号只在真正存在的时候写。

| 缩写 | 全称 | 公式 | 坑 |
| --- | --- | --- | --- |
| TT | Takt Time 节拍时间 | 可用生产时间 ÷ 客户需求量 | 「可用时间」是否含加班、客户量是月均还是当周，两种口径能差 20% |
| CT | Cycle Time 周期时间 | 一个工件完成一道工序的实际时间 | 有时指设备节拍、有时指含等待。写进字段名要加前缀：`proc_ct` vs `order_ct` |
| LT | Lead Time 交付前置期 | 从下单到交付 | 对外承诺的是 LT，对内优化的是 CT。混用会让你以为自己有 3 倍余量 |
| MLT | Manufacturing Lead Time 制造周期 | 加工 + 等待 + 搬运 + 检验 + 排队 | ≈ 加工时间的 5~20 倍。排队才是大头，这也是为什么调度规则比加工优化更值钱 |
| FTT | First Through Time 首次通过时间 | 工件在流程里走完第一段的耗时 | 用于评估**新订单的可见交付时间**，比 MLT 更早暴露问题 |
| WIP | Work In Process 在制品 | Little 定律：`L = λ · W` | 三量同单位才能乘。件、天、件/天是标准组合 |
| Little 定律 | — | 稳态下 `平均 WIP = 平均到达率 × 平均停留时间` | 前提是**稳态**。插单占比 50% 的车间不满足，结论只能当方向感 |
| OTD | On-Time Delivery 准时交付率 | 按时交付的订单 ÷ 全部订单 | 分母含不含延期后已重确认的订单？口径要写死在 SQL 里 |
| OTIF | On Time In Full | 按时**且足量**交付 | 比 OTD 严。部分交付在军品里通常等于不算数 |
| FPY | First Pass Yield 直通率 | 一次做对、不经返修的合格品比例 | 全链路 FPY = 各工序 FPY 连乘。50 道工序 × 99% ≈ 60%，这就是为什么返工是产能黑洞 |
| RTY | Rolled Throughput Yield | 同上，连乘口径 | 与 FPY 常混用；差别在于 RTY 明确用连乘 |
| CO | Changeover 换型 | 见第三节 换型 | 有的厂把 CO 当指标（换型损失工时），和上面的动作是两个东西 |
| Kingman 近似 | Queueing | `E[W] ≈ (−ln P)` 形式的重流量近似，利用率 ρ→1 时等待时间发散 | 它告诉你**排队时间是凸函数**：利用率从 85% 提到 95%，等待时间翻倍还不止 |

## 五、工艺与质量（军品/航空特色）

这一节的词，**民用厂多半没有**。但它们是硬阻断约束，漏一个就会做出「数学最优、现场违法」的方案。

| 术语 | 一句话 | 为什么它是约束 | 出处等级 |
| --- | --- | --- | --- |
| 工序域 | 按工艺性质切分的大域：机加、锻造、钣焊、热表、装配、试车、大修 | 跨域协调是 M 级智能体的职责，同域内部才轮到设备排程 | B |
| 关重件 | 关键件 + 重要件，质量管控分级 | 关重件要素上的缺口直接判「阻断开工」；它的齐套判定比普通件严 | B（分级细则各厂不同） |
| 特殊过程 | 结果不能通过后续检验完全验证的过程：焊接、热处理、表面处理、胶接、无损检测 | 因为「检不出来」，所以**人、机、料、法、环的资质与参数必须前置校验**，不能靠事后把关 | A：定义思路见 GJB 1405A-2006（条文原文请自查） |
| 特殊过程有效期 | 过程完成后须在有效期内进入下道（如钛合金焊接 20 天） | 跨工序的时间窗硬约束，且**跨节假日仍衰减**。违规必须硬阻断，不允许人工放行 | C（数值是企业口径） |
| 军检节点 | 需军代表到场检验的停点 | 它是一条**外部资源**，你不控制它的日历。排产里当预约型约束 | B |
| 关键工序「三定」 | 定人员、定设备、定工艺（各厂表述不一） | 若成立，就是 `x[i,j,k]` 上的一组**允许组合白名单**，不是软惩罚 | <span class="psa-chip">口径未核实</span> |
| 「1 图 4 表 2 规范」 | 关键工序的工艺文件齐套要求（图示 + 四种表 + 两种规范） | 文件不齐 → 工序不许开工。本质是**文档状态的布尔量**，要做成实体不是字段 | <span class="psa-chip">口径未核实</span> |
| 两装两试 | 装配不合格 → 再装配 → 再试车的返工回路 | 它让工序链变成**有环图**，你的拓扑排序会直接抛异常。返工概率是随机的 | C |
| 返工 / 让步 / 报废 | 三种不合格处置结论 | 返工回炉、让步降级、报废重做——三者对产能的影响完全不同 | A（术语）/ B（判定流程） |
| 探伤合格率 | 无损检测的一次通过率（LISA 现状 60%） | 40% 的概率要走返工回路。**这就是不确定性必须进模型的原因** | C |
| 贯改 / 排故 | 技术状态改归与故障排除（LISA：占月订单约 50%） | 一半的「订单」其实是返工与整改。没有标准流程时，你的产能基线本身就不可信 | C |
| ECN | Engineering Change Notice 工程变更通知 | 变更会**追溯**在制品：已开工的工单要不要停？这是涟漪推演的输入 | A（术语） |
| 涟漪推演 | 一处扰动沿工艺链向后传播的影响面评估 | LISA 要求 ≤15min 出 A/B 方案。它不是重排，是**传播计算**，比重排便宜得多 | C |
| 白盒归因 | 每个方案要说清「为什么这么排」 | 采纳率 <span class="psa-chip">≥85%</span> 的前提是可解释。黑盒最优方案在现场等于零分 | C |

## 六、约束、目标与解的质量（数学口径）

| 术语 | 英文 | 含义 | 坑 |
| --- | --- | --- | --- |
| 完工时间 | Makespan `C_max` | 最后一件活完成的时刻 | 「最小化 makespan」≠「不逾期」。交期在模型里是另一组约束 |
| 完工时刻 | `C_j` | 工件 j 的完成时间 | 变量定义要写清是**工序级**还是**工件级**，两者差一层 max |
| 延迟 / 拖期 | Tardiness `T_j = max(0, C_j − d_j)` | 早到不算 | 和 Lateness 的区别就在 max(0,·)。早到算负的话，目标函数会奖励「提前压任务」 |
| 最大滞后 | `L_max` | `max(C_j − d_j)` | 一个数管所有交期，但对少数晚点极敏感 |
| 加权拖期 | `Σ w_j T_j` | 不同工单权重不同 | 权重是政治不是数学。让计划员给 `w`，别让他评价你的目标函数 |
| 流动时间 | Flow Time `F_j = C_j − r_j` | 工件在系统里的总停留 | SPT（最短加工时间优先）单机的最优目标就是这个 |
| 硬约束 / 软约束 | Hard / Soft Constraint | 前者不可违反，后者违反计罚 | 现场真正硬的东西比数学上硬的多（资质、有效期、军检）。把硬约束写成大罚权重的软约束，求解器一定会违反它 |
| 大 M 法 | Big-M | 用 `x ≤ M·y` 把逻辑条件写进线性模型 | M 取太小丢可行解，取太大数值崩溃。这是 MILP 排产最常见的「解不对」根因 |
| 松弛 | Relaxation | 去掉一部分约束换来的更易解问题 | 松弛的解是给**下界**用的，不是给你交差用的 |
| 下界 / 上界 | LB / UB | 最优值一定夹在中间 | LB 来自松弛或对偶，UB 来自可行解。**报告 gap，不要报告「最优」** |
| 间隙 | Gap `(UB − LB) / UB` | 你的解和未知最优最多差多少 | gap 3% 是好消息，gap 40% 也是信息。没有 LB，你根本不知道自己在哪 |
| 对偶乘子 | Dual Multiplier `λ` | 拉格朗日松弛里每单位资源稀缺的价格 | 它不是装饰：λ 大 = 这条资源在打架，是现场最该看的地方 |
| 影子价格 | Shadow Price | 约束右端 +1 单位，目标改善多少 | 只在**当前基**有效，跨一个拐点就失效。别拿它做长期报价 |
| 弱对偶 / 强对偶 | Weak / Strong Duality | 原问题最优 ≥ 对偶任意值；何时取等 | MILP 整数间隙（integrality gap）非零时，取不到等——这就是 gap 的来源 |
| Pareto 前沿 | Pareto Front | 一组互不支配的解 | 「多目标加权求和」**取不到非凸前沿上的点**（Das–Dennis 1997 的盲区） |
| ε-约束法 | ε-Constraint | 一个目标优化，其余约束化 | 能拿非凸点，但 ε 取值要会调，否则前沿有空洞 |
| 字典序 | Lexicographic | 目标严格分优先级 | 表达的是「政治优先级」，一旦排错顺序，后面的优化全在为错误的第一目标服务 |
| 重排 | Rescheduling / Reactive Scheduling | 扰动后生成新计划 | 好坏由两个目标衡量：**新计划本身的质量** + **与旧计划的偏离度**（稳定性）。只优化前者，现场会骂你 |
| 冻结策略 | Right-shift / Partial fix | 只右移不左移 / 锁一部分重排 | Right-shift 简单但会让计划一路漂移；这就是「冻结窗口」在数学上做的事 |

## 七、系统与接入

| 缩写 | 全称 | 管什么 | 坑 |
| --- | --- | --- | --- |
| ERP | Enterprise Resource Planning | 财务、采购、订单、BOM、MPS/MRP | 它的「产能」通常是无限的或是一个系数。不要指望它做有限产能 |
| MES | Manufacturing Execution System | 工单执行、报工、过站 | 每个厂都改名。同一类产品叫 MOM / MES / 生产管理系统，别按名字对接 |
| MOM | Manufacturing Operations Management | MES 的上位概念（ISA-95 语境） | 与 MES 的边界各厂商说法不一，以**接口清单**为准 |
| APS | Advanced Planning & Scheduling | 有限产能排程引擎 | APS 是**产品**，不是**项目**。装上不会自己变准，规则与数据要人喂 |
| PLM / PDM | Product/Process Lifecycle & Data Management | 图纸、工艺路线、版本、ECN | 工艺路线的**版本有效性**是排产正确性的地基。用错版本，全厂排错 |
| QMS | Quality Management System | 检验、不合格、资质 | 检验结论与人员资质是齐套要素，不是质量报表 |
| WMS | Warehouse Management System | 库存、库位、批次 | 可用量 = `on_hand − allocated`，还要过质量状态与效期 |
| SCADA / PLC | Supervisory Control and Data Acquisition | 设备信号 | L0 层。它给的是「在动」，不是「在做什么」，中间缺一层工单绑定 |
| ISA-95 / IEC 62264 | Enterprise-Control System Integration | L0 物理 → L1 传感控制 → L2 监控 → L3 制造运营 → L4 商务 | A Level 4 的计划**不能直接下发到 L2**。跨层要经 L3，这是行业公认的边界 |
| 主数据 | Master Data | 物料、设备、工艺、人员的编码与属性 | 「MOM 与 ERP 编码不统一、图号 ↔ 物料号对不上」是排产项目的第一杀手 |
| MCP | Model Context Protocol | 让模型以 JSON-RPC 2.0 发现并调用工具 | 排产场景里只暴露**只读**工具；`apply_` / `approve_` / `write_` 这类前缀必须禁止注册 |
| 工具 / Tool | MCP `tools/list` 返回的可调用能力 | 参数是 JSON Schema | 工具的 description 是提示词的一部分，写含糊了模型就会误用 |
| 本体 | Ontology | 概念、属性与关系的正式定义（OWL / RDF） | 本体不是 ER 图：它允许推理。「焊接属特殊过程 ⇒ 需资质」这句话只有本体能承载 |
| 知识图谱 | Knowledge Graph | 本体实例化后的图（Neo4j 等） | 图谱查询快不等于图谱可信。写入侧要有 SHACL 校验，否则是垃圾加速器 |
| SHACL | Shapes Constraint Language (W3C) | 对 RDF 图做形状约束校验 | 它是**护栏**：违规硬阻断，不能降级成 warning |
| PROV-O | W3C Provenance Ontology | 「谁、用什么、怎么得到这个结论」的建模 | 审计链要能回放：方案 → 输入快照 → 规则版本 → 求解器与参数 |
| RAG | Retrieval-Augmented Generation | 检索后塞进上下文 | 排产里 RAG 不能替代约束校验。检索到的规则可能已过版本 |

## 八、Agent 与落地

| 术语 | 一句话 | 坑 |
| --- | --- | --- |
| 原子级智能体 A | 单工序域内的排产建议者（LISA 里 A-01~A-07 + A-00 数据点检） | 它是 **Copilot**，只读、出 A/B/C 三方案，不写库 |
| 分子级智能体 M | 跨工序、跨域的协调者（LISA M-01~M-06） | 它负责**协调**：齐套编排、涟漪推演、外协、特殊过程联动，不负责寻优 |
| 化合物级智能体 C | 全局总控与战略（LISA 2 个） | 别让它直接下指令。它的输出是**决策建议 + 依据** |
| 五大模块 | 感知 / 记忆 / 推理 / 行动 / 反思一类的通用切分 | 各家叫法不同；LISA 原文没有统一的「五模块」命名，别照抄别人的 |
| Harness | 编排外壳：状态机、重试、超时、降级 | 排产是长事务（跨日审批）。用工作流引擎，不要用「asyncio 加定时器」 |
| 只读工具面 | Agent 只能查、不能改的接口面 | 这是**架构约束**，不是提示词。注册 `apply_` 就报错，比写十句「请不要修改」有效 |
| 写入熔断 | 任何写库动作的强制闸门 | 熔断要落在**服务端**（校验身份、范围、审批状态），不在客户端 |
| 渐进授权 | 按场景从「建议」升到「半自主」再到「自主」 | 分级依据是采纳率与场景风险，不是模型自信度 |
| 影子模式 | 系统出方案但不生效，与人工方案并行留档 | 影子期最重要的产出是**人机分歧清单**，不是准确率数字 |
| 影子回校 | 实绩与计划的偏差回流，T+1 修正模型 | 需要「计划—实际」可对齐的主键。没有基线快照就回校不了 |
| 采纳率 | 方案经计划员确认后可直接下达、无需结构性修改的占比 | 「结构性修改」怎么定义要写死。否则一条改 200 处和改 1 处都算「采纳」 |
| 人机分歧 | 系统建议与人工决定不一致的案例 | 逐条分类：数据错 / 规则缺 / 目标不符 / 现场信息没进系统。**这四类的修法完全不同** |
| 形态四档 | 按采纳率分档：<60% 观察、60~75% 建议、75~85% 半自主、≥85% 自主 | 数字是 LISA 项目的口径，不是通用阈值。跨厂要重新定 |
| 白盒归因 | 每个结论能指出触发了哪条规则、用了哪些数据 | 归因要引用**规则编号**，不是自然语言解释。自然语言解释不可验证 |
| 审计链 | 决策全过程可回放 | 链要防篡改：库内哈希链 + 库外锚点。只在库里存，等于没存 |
| ABAC | Attribute-Based Access Control | 按属性授权，能表达「密级 ≥ 且 厂区 = 且 域 ∈」 | 密级与厂区是**叠加**过滤，不是二选一。任一通道漏一层就是泄密 |
| 脱敏 | 敏感字段以替代形态呈现 | 脱敏要在服务端做，别指望前端 CSS 或模型「自觉」 |

## 十、三个建议

1. **建一张术语字典表。** 字段至少要有：`term` / `alias` / `definition` / `source_level`（A 标准号 / B 行业 / C 本厂）/ `source_ref` / `unit` / `owner`。
   这张表本身就是通识数据集的一部分，LISA 里叫「通识数据集 T1」。
2. **口径写进 SQL，不写进 wiki。** 「齐套率」的分母如果在 wiki 里，三个月后没人知道自己看的是哪个数。
   把它做成一个视图，指标页直接查视图。
3. **C 类词全部做成配置。** 「3 锁 1」的 3 是天数还是周数、「满炉率」的分母是什么——
   这些都是**参数**。硬编码的结果是：换一条产线，代码 fork。

## 十一、「口径未核实」清单

下面这些词，本手册**没有找到可以引用的标准原文**。它们要么是企业内部口径，要么是行业习惯说法。
照抄进你的需求文档之前，去问一个真正的计划员。

| 词 | 我们的状态 | 建议动作 |
| --- | --- | --- |
| 冻结窗口 / 时间围栏 / Time Fence | 有广泛行业用法，**无国标定义**。LISA 文档给的是「周计划前 3 天锁定期」 | 按厂配置；文档里注明「本项目口径」 |
| 周滚动 3 锁 1 下发 3 展望 | 原文照录，**单位（天/周）未注明** | 需求评审第一个问题 |
| 满炉率 | 概念清楚，**公式无标准**（格数 / 重量 / 有效加热区体积？） | 让热表车间自己给公式，写成视图 |
| 转序 | 行业通用，**无标准定义**，各系统状态名不同 | 映射到你们 MES 的状态枚举，不要新建概念 |
| 关键工序「三定」 | 常见说法，**具体条目各厂不一** | 当作白名单约束的数据，不当作定理 |
| 「1 图 4 表 2 规范」 | 企业工艺文件做法，**未找到标准原文** | 让工艺部门给清单，逐条建模成布尔字段 |
| 特殊过程范围 | 定义思路可参照 GJB 1405A-2006，**本手册未核对条文原文** | 以你所在体系的正式受控文本为准 |
