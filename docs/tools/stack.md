# 求解器与技术栈选型表

选型表有两种写法。一种是罗列功能打星，那种表谁都能写；
这一页只回答三个会被写进合同的问题：

1. **求解内核选谁** —— 按规模、约束形状、合规要求三问，不按名气；
2. **每个组件「什么时候不该选它」** —— 反向条件比正向卖点有用十倍；
3. **三个典型场景的现成答案** —— 军工合规、预算为零、交互式重排。

:::: warning 本页的立场
本页是**选型器**，不是排行榜。表格里的排序会随你的规模、精度要求、约束形状、重排频率、
数据成熟度五个答案变化（互动版见[首页选型器](/)）。抄结论之前先回答那五个问题。
::::

## 一、求解内核：一页表定去留

| 内核 | 许可证 | 强项 | 什么时候**不该**选它 | 一句话 |
| --- | --- | --- | --- | --- |
| OR-Tools CP-SAT | Apache-2.0 | 排产类约束（`no_overlap`/`cumulative`）+ 时序传播器，多线程，免费里最能打 | 需要商用支持 SLA；LP 松弛很强的纯连续问题 | 排产起步的默认答案 |
| Gurobi | 商业 | MILP 求解性能标杆， LP/QP 全家桶，技术支持到位 | 预算按核数计费、军工内网拿不到许可 | 预算充足 + MILP 为主 |
| 杉数 COPT | 商业（国产） | 国产 MILP/SOCP，性能一线，**供应链与信创合规友好** | 纯开源要求；无采购通道 | 合规压过预算时的选择 |
| HiGHS | MIT | 纯 LP/MIP，轻量可嵌入，无依赖 | 大规模 CP 结构（它没有传播器） | LP 层和教学项目的底座 |
| SCIP | Apache-2.0（8.0.3 起） | 混合整数，约束整数规划学术血脉 | 商用支持与 COPT/Gurobi 比仍弱 | 想要「比 CP-SAT 更可定制」时的折中 |
| Timefold (OptaPlanner 后继) | Apache-2.0 | Java 生态、开箱即用的排班/车辆问题领域模型 | Python 技术栈；约束极不标准的现场 | Java 团队 + 标准场景 |
| 自研（规则 + 局部搜索） | — | 完全可控、可解释、零许可风险 | 有人指望它「最优」 | 永远要有这一档，它是降级链的底 |

三条经验法则：

- **CP 结构（互斥、时窗、换型）占约束大头 → CP-SAT 起步**。排产的约束形状天生是 CP 的主场，
  传播器把 `(n!)^m` 的空间砍到能搜（见[精确算法](/problem/exact)）。
- **目标函数是线性 + 大规模连续决策（选矿配比、切裁）→ MILP 系**（Gurobi/COPT）。
- **任何情况下都准备一档「规则派单 + 局部搜索」**。求解器会在你最需要的时刻崩溃
  （[实测](/build/code)），降级链的第一档永远是自研（见[写保护、熔断与降级链](/arch/guardrail)）。

- **军工 / 信创内网**：求解器许可必须在无外网环境可验证；LLM 必须私有化部署；
  「客户、图号、人名」进模型前脱敏成占位符（做法见[护栏页](/arch/guardrail)）。
- **预算为零**：CP-SAT（Apache-2.0）+ HiGHS（MIT）+ 自研规则档，能覆盖从教学到中型工厂的绝大多数起步需求；
  本站[代码页](/build/code)的 450 行脚本就是这个组合的最小骨架。
- **交互式重排**：先做增量评估（实测 2.1 倍起步，越大越赚，见[性能页](/build/perf)），
  冻结窗口按时间不按序列前缀，右移修复档永远排在全量重排前面。

## 三、内核之外的六件套

求解器只占排产系统的一小块。剩下的选型，按「它在哪个失败模式里救你」来定：

| 组件 | 干什么 | 够用的起步选择 | 什么时候升级 |
| --- | --- | --- | --- |
| LLM 层 | 听懂人话、翻任务、解释方案 | 任意强模型 + 严格只读工具面 | 私有化/合规要求出现时 |
| MCP 网关 | 把 MES/ERP 能力收进统一工具面，`readOnlyHint` 分级 | 手写一个只读 catalog 起步 | 工具数过 20、入参过 50 时上网关 |
| 本体 / 图谱 | 工艺路线 DAG、设备能力拓扑、SHACL 护栏 | 关系库 + 代码里的校验器 | 跨厂协同、本体复用需求出现时 |
| 规则引擎 | 68 条那种「车间法令」的显性化 | 配置表 + 校验函数 | 规则要被计划员自己维护时 |
| 评测 | 影子模式、人机分歧、回归算例库 | 算例库 + 每日批跑 + 报表 | 采纳率考核进 KPI 时 |
| 工作台 | 甘特差分、白盒归因、电子签名 | 只读甘特 + 导出 | 计划员真拿它排产时 |

这些组件各自的深入分析：[MCP 接入层](/arch/mcp)、[本体与护栏](/arch/ontology)、
[评测](/build/eval)、[调度员工作台](/build/workbench)。

## 四、选型表救不了的三个决定

1. **「先跑 POC 还是先修数据」**——永远先修数据。求解器换型是两周的事，
   BOM/工时口径失真是两年的事（[先修数据，再谈智能](/build/data-first)）。
2. **「自研内核还是上求解器」**——都要。自研档是降级链的第一层和可解释性的底座，
   求解器是精确档的加速器。二选一的项目说明书都没读完。
3. **「买商业求解器值不值」**——只有拿你自己的算例跑出过基线才有资格讨论。
   先用 CP-SAT 把同一算例解一遍，那个 gap 就是商业许可的上限价格。
