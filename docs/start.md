# 这本手册怎么读

这本手册是给**要动手做 production-scheduling-agent 的程序员**看的。
它假设你会写代码、看得懂伪代码、知道什么是数据库索引，但**不假设你学过运筹学**。
它也假设你从没进过机加工车间，所以每个现场名词第一次出现时都会被翻译成人话。

排产这个项目有个特点：**它是少数几个「数学很难 + 数据很脏 + 人很多疑」三件事同时成立的方向**。
只补一课的人必翻车。所以手册按四条线铺：

## 一、四条线，和它们各自的失败模式

| 线 | 讲什么 | 你不读它会怎样 |
| --- | --- | --- |
| [数学与算法](/problem/np-hard) | 问题为什么难、能用哪些定理、怎么知道方案好不好 | 你会写出一个「跑得出结果但没人敢用」的优化器，或者花三个月自己实现一个已经被超越二十年的算法 |
| [系统架构](/arch/seven-layers) | 七层底座、三级智能体、MCP、护栏、审计 | 你会把大模型直接接到 MES 上，然后在第一次幻觉事故后被永久禁用 AI |
| [实战案例 LISA](/case/background) | 一个航空发动机厂的真实数字、真实约束、真实验收条款 | 你会以为需求是「排得更快」，而客户写的验收其实是「采纳率 ≥85%」和「硬约束违背率 = 0」 |
| [工程落地](/build/roadmap) | 路线图、数据治理、评测、性能、代码、避坑 | 你会在演示会上很风光，然后在上线第三个月被计划员退回 Excel |

## 三、出处纪律：每页数字后面都跟着来源

手册里的数字只有三类，**分类标注**：

- **定理与复杂度结论** —— 给出学者与年份（例如「JSP 强 NP-hard：Garey–Johnson–Sethi, 1976」）。这类是硬事实，可以直接拿去和同事争。
- **LISA 案例数字** —— 来自项目文档（业务调研、问题提炼与目标对齐清单、架构设计说明书、投产配置清单）。这类**文档之间互相矛盾**，手册的做法是把两个口径都写出来并注明出处，不替你抹平。
- **行业与市场数字** —— 来自公开报道与厂商材料。这类我会明确标出哪些是「厂商自宣」、哪些「未能核实一手来源」。

这不是形式主义。排产项目里最容易死的方式就是：**你的算法用的工时基准和车间用的不是同一套数**。
手册先把「口径不一致」摊开给你看，是为了让你在真实项目里能认出它。

## 四、动手前置

`build/code` 那一页的可运行代码只需要：

```bash
python 3.10+          # 只用标准库的部分不需要任何安装
pip install ortools   # CP-SAT 示例，约 30MB，纯 CPU
pip install mcp       # 只读工具面示例
```

求解器示例默认用开源 OR-Tools（Apache-2.0）。提到商用求解器（COPT / Gurobi / CPLEX / IBM CP Optimizer）时，
我只讲**接口形状和授权约束**，不假装我有 license。
