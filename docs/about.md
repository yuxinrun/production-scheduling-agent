# 关于本站

## 这是什么

一本写给**要做 production-scheduling-agent 的程序员**的手册。
它不讲「AI 改变制造业」，讲一个具体的工程问题：怎么让程序替计划员决定
「哪张工单、在哪台设备、从几点到几点、干什么」，并且这个决定在现场能被执行、能被追责、能被回放。

它的坐标是一个交叉点：一半是**数学**（强 NP-hard、对偶、多目标、随机扰动），
一半是**软件**（数据口径、系统集成、权限、审计、UI）。只学一边的人在这种项目里一定会翻车。

## 怎么读

三条路线按你是谁选，[首页第八节](/)有完整版：

- **只想知道能不能做** → [排产 Agent 到底是什么](/what-is)、[它不是 APS](/not-aps)，看数字就行；
- **要写代码** → [15 分钟跑通一个最小排产内核](/build/code) 起步，数学与架构章节精读；
- **要写方案** → 实战案例九页是现成的骨架，[当模板抄](/case/background)。

## 数字从哪来

三类出处，页面上每次引用都标了：

1. **运筹学结论** —— 给论文与教材（清单见[参考资料](/references)）；
2. **案例数字** —— 来自一个已脱敏的航空发动机厂排产项目（见下节），页面上可复算的都给了脚本；
3. **行业数字** —— 公开报道与转载数据，**未能核实的照写不误并注明**，口径冲突的把两个口径都写出来。

站内所有「实测」标注的数字都能用仓库里 [`/snippets/`](/snippets/) 的脚本离线复跑，
纯标准库为主，每页开头写了运行时长。换机器会变的只有耗时，结论不会。

## 案例脱敏说明

实战案例（LISA）来自一个真实的军工背景排产项目。**客户与咨询方的名称、组织架构细节均已匿名化**，
项目文档原文不随本仓库分发；案例页引用的全部数字已内联进页面与脚本，
脱敏不影响任何结论的可复算性。

## 内容许可

- 文字与插图：除非另行注明，本站内容供**学习与内部评审**自由引用，转载请注明出处与本站链接。
- 代码：[`/snippets/`](/snippets/) 下的脚本没有任何许可约束，拷走改完就用，
  但请保留种子与口径注释——那是「可复现」的一部分。
- 页面上引用的第三方商标与项目名（OR-Tools、Gurobi、COPT、MCP 等）归各自权利人所有。
