# 12 题自测

排产项目的面试题和验收题，一大半考的不是算法，是**语义**：
「有限产能」是约束还是报表、下界能不能写进合同、写动作该不该出现在只读工具面。

这 12 题全部是单选，答完立刻判分并给出解释。
**答错的每一题都对应真实项目里翻过一次的车**——题目下方标了出处页，翻回去补那一页就行。

## 分档怎么看

- **11~12 对（可以上线）**：数学、排产语义、工程护栏都对得上。缺的只有真实数据——去把[五维点检](/build/data-first)跑起来。
- **7~10 对（能干，但会被现场打脸）**：概念没问题，坑在「口径」：齐套要素归口、冻结窗口、关重件阻断，没一条是算法问题。
- **5~6 对（别急着自己写求解器）**：先把 NP-hard 为什么、CP 的传播器、以及「有限产能是约束不是报表」吃透。
- **≤4 对（建议从头读起）**：这不是你的错——排产领域的坑一大半不在算法里。先读[排产 Agent 到底是什么](/what-is)和[术语表](/glossary)。

## 做完之后

- 全对的，去 [15 分钟跑通一个最小排产内核](/build/code) 把第一行代码写掉。
- 03/04 错的，[拉格朗日](/problem/lagrangian) 页有个可以按步播放的次梯度迭代器，亲手跑一遍比读十遍有用。
- 06/07/08 错的，说明你在用「软件思维」学排产——先读 [它不是 APS，也不是聊天机器人](/not-aps) 纠偏。
- 10/11 错的，你的架构缺的是权限层不是模型层，[MCP 只读工具面](/arch/mcp) 和 [护栏](/arch/guardrail) 两页按顺序读。
- 12 错的，去 [采纳率是个组织问题](/build/adoption) 看看 APS 采纳率 20~30% 的调研数字是怎么来的。
