## 0. 执行摘要（一分钟看懂）

- **客户**：中国航发贵州黎阳航空发动机有限公司（AECC Liyang，军工航空发动机离散制造，两厂区/10 个分厂/七大工序域：机加、锻造、钣焊、热表、装配、试车、大修；108 个核心产品 × 28 道工序）。

- **本质约束（军工四性）**：① 可追溯（决策链路留痕、PROV-O 血缘、军工审计）；② 可兜底（规则兜底、人工确认、熔断降级、渐进授权）；③ 可解释（白盒归因 A/B 方案）；④ 安全合规（私有化部署、数据不出内网、脱敏不可逆、ABAC、密级管控）。
- **技术栈结论**：**Python 智能体编排（LangGraph + MCP/A2A）+ Java MCP 适配层（Spring Boot 3 + CXF 对接 SAP/遗留系统）+ 杉数 COPT 求解器 + 本体知识图谱（Jena + Neo4j + SHACL）+ RocketMQ 事件总线 + Vue3 调度员工作台**；全栈自研、国产化优先、私有化部署。
- **本项目英文名建议**：主推 **LISA（Liyang Intelligent Scheduling Agent）**；备选 **AeroSched**（对外品牌）、**Liyang Aero-APS**（系统层别名）。

## 2. 客户是谁、项目是什么

### 2.1 客户背景

- 中国航发贵州黎阳航空发动机有限公司，军工航空发动机整机/零部件离散制造企业。
- 生产特点：**多品种、小批量、长流程、强约束**——军品紧急订单占比高、关重件管控、特殊过程有效期（如钛合金焊接 20 天）、军检节点、外协依赖、两装两试返工回路。
- 现有 IT：MES（制造执行）、ERP/SAP（企业资源）、QMS（质量）、WMS（仓储）、PLM（工艺）、HR/EAM（人员/设备），另有 APS 排产（钣金焊接、部装），以及 OpenTrek（阿里云智能体工厂 V3.18.6，专有云）作为咨询方预设的智能体底座。
- 咨询方：上海承丰（已交付 9 大类成果：调研现状、业务模式设计、智能体定义、本体方案、数据集设计与标注模板、MCP 方案、能力点检、MVP 清单、培训材料）。

### 2.2 项目定位

- 项目全称：**黎阳智能排产智能体（AI 先锋项目）**。
- 本质：用**知识驱动 + 运筹优化 + 大模型推理**的三级智能体体系，替代/升级现有"固定参数 APS + 人工经验排产"，实现**有限产能、规则化、可解释、可追溯**的排产闭环。
- 它不是普通的 APS 系统，也不是纯 LLM 应用，而是**"运筹求解器 + 规则引擎 + 知识图谱 + LLM 智能体"四层融合系统**，LLM 只做编排、解释与兜底，绝不做数值排产的唯一决策源。

## 4. 技术栈推荐（符合智能体架构规范）

### 4.1 总体判断

客户咨询方案以 **OpenTrek（阿里云专有云智能体工厂 V3.18.6）** 为底座，56 项能力点检结果为：满足 21 / 部分满足 25 / **不满足 10**（运筹求解器 LP/MIP/启发式/增量/数值稳定性 5 项、本体建模与 SHACL 校验及图谱推理 3 项、消息队列 1 项、DAG 分析组件 1 项），缺口全部靠外挂组件补齐。

**对开发承接方的建议**：本方案按"全栈自研为主"设计（代码级可控、可审计、无平台绑定风险，且外挂组件数量与自研重叠度高），但保留两套路线对照（见 4.5）。若客户坚持 OpenTrek 底座，本方案的分层组件均可作为 OpenTrek 的外挂能力（COPT/Neo4j/SHACL/RocketMQ 已在点检清单中确认为外挂项），技术选型不变。

### 4.2 分层技术选型总表

| 层 | 模块 | 推荐技术 | 理由 / 对应资料依据 |
|---|---|---|---|
| L6 安全 | 认证鉴权 | Keycloak（OAuth2/JWT）或国产统一身份平台 | MCP 方案要求 OAuth2 Resource Server 校验 JWT |

### 4.3 关键架构决策点（为什么这样选）

1. **为什么编排用 LangGraph 而不是 OpenTrek/Coze/自研**：军工项目要求"推理可追溯、状态可恢复、层级权限可控"。LangGraph 的显式状态机、检查点（断点恢复）、条件边、人工中断（human-in-the-loop）与三级智能体 C/M/A + 审批回路天然匹配；且它不锁平台，可整体私有化。若团队 Java 栈更强，可用 Spring AI + LangGraph4j 对应替代，但求解器/算法库/本体工具链 Python 生态更成熟，故**主栈 Python + Java 适配层**。
2. **为什么 MCP 适配层用 Java（Spring Boot 3）**：SAP/MES 等遗留系统走 SOAP/WSDL 与数据库直连，Java 的 CXF/连接池/TLS 信任库生态最稳；MCP 方案文档已明确给出该技术组合（Spring AI MCP Server Starter），可直接复用其"任务清单"（WSDL 桩生成→DTO 映射→@Tool→鉴权脱敏→治理）。
3. **为什么求解器选 COPT**：军工国产化硬约束 + 点检清单明确"平台不含求解器，须外挂 COPT 集群"。COPT 覆盖 LP/MIP/启发式/增量热启动，支持 15s 超时熔断、不可行 IIS 诊断（数值稳定性要求）。**关键工程要点**：求解结果必须过 SHACL/HC 护栏 + 规则引擎双校验后才能呈现，避免"数学上最优、业务上违法"。
4. **为什么需要本体 + 图谱 + 向量三件套**：68 条规则、137 条约束、840 案例、600 经验需要在"数据—语义"双链路下可解释地召回与推理（HC-05 业务闭环、HC-12 工序依赖闭环、M-04 涟漪推演）。纯 RAG 无法保证约束可校验，纯图谱无法支撑语义召回——三件套缺一不可，且以本体为单一语义源（SPARQL 可查、Cypher 可推、向量可召回、SHACL 可校验）。
5. **为什么事件总线必须独立（RocketMQ）**：插单、故障、缺料、齐套变化、军检提交等事件是触发重排/影响评估的唯一可靠通道；点检清单确认平台不满足，须外挂。消息不丢不重（投递可靠性≥99.99%）是"变更评估≤15min/局部重排≤30min"的信息流前提。
6. **写入保护为什么是独立网关**：LLM 与求解器一律不直连 APS/MES 写接口。所有"写"走 `写保护网关 → 审批（A/B 方案）→ 电子签名 → 回写 APS 基线`，未审批写入拦截率 100%。这是军工合规的物理边界，不是可选项。

### 4.4 技术风险与兜底

| 风险 | 等级 | 缓解措施 |

  - M（分子级/跨工序协调）：M-01 机加-热表链式、M-02 装配-试车联动、M-03 齐套检查（9 要素三时点硬阻断）、M-04 变更影响面评估（≤15min 涟漪推演、A/B 方案）、M-05 外协协调、M-06 特殊过程联动（有效期硬校验）。
  - A（原子级/单工序排产）：A-00 数据点检与产能核算、A-01~A-07 七大工序排产。A 级只读建议，M 级编排，C 级总控。
- 验收 KPI：采纳率≥85%、夜间全量重排 1~2h、变更评估≤15min、局部重排≤30min、装配齐套率 60%→100%、试车日计划达成率提升；一期排产准确率≥60%（专识数据四区间 9.8k→26k→46.7k→68.9k 条渐进达成）。
- 规则底盘：68 条排产规则（ZD-01-2026-R001~R068）+ 137 条约束（硬约束 HC-01~14 违反即阻断不可放行、软约束 SC 权重 0.02~0.35）；本体 7 核心类（Order/Part/Operation/Resource/Constraint/Disturbance/Plan）。

## 系统架构（7 层，开发时必须落盘为代码结构）
L0 数据基座（五维点检≥90%门禁）→ L1 感知接入（MCP 只读 + RocketMQ 事件）→ L2 智能体编排（LangGraph 三级智能体 + ReAct + 状态机）→ L3 能力组件（COPT 求解/规则引擎/SHACL/小模型）→ L4 数据知识（PostgreSQL + Milvus + Neo4j + Jena 本体）→ L5 评测治理（指标/影子回校）→ L6 安全（ABAC/写入熔断/审计/脱敏）。

## 硬性工程纪律（违反即返工）
1. 可追溯：每一次排产决策（LLM 推理链、工具调用参数、求解输入输出、规则命中、审批人/时间/意见）都必须落审计日志，格式统一、可回放。代码中所有对外写操作必须过"写保护网关+审批"。
2. 可兜底：任何环节异常都有降级路径（求解超时→启发式→规则兜底→人工接管），禁止静默失败或直接报错中断业务。
3. 可解释：每个排产方案必须携带白盒归因（命中了哪些规则/约束、为什么这样取舍），A/B 方案对比输出。
4. 安全合规：数据脱敏不可逆、密级标识、私有化部署、无公网依赖；禁止把涉密数据写入日志明文。
5. 国产化：求解器用杉数 COPT 接口、消息用 RocketMQ、大模型用国产私有化模型（通过 OpenAI 兼容 API 接入）。
6. 契约化：所有 MCP 工具/API 必须有 OpenAPI/JSON Schema 契约与错误码定义；工具参数白名单校验。
7. 数值可信：LLM 输出的任何数值/规则结论必须先经数据底座或规则引擎核验才能呈现；求解结果必须过 SHACL/HC 护栏校验。

| P1（4~6 周） | 本体 + SHACL + Neo4j + RAG；规则引擎（68 条）；COPT 求解封装 | 区间一（9.8k）粗排链路跑通 |

| P4（收尾） | 安全加固（ABAC/熔断/脱敏）、国产化适配、压测、文档 | 验收评审 |

### 7.3 术语速查

- **P0/P1 订单**：军品紧急 / 军品+关键重要件（约占订单 60%）。
- **关重件**：关键件、重要件（质量管控分级）。
- **特殊过程**：结果不能通过后续检验完全验证的过程（焊接、热处理、无损检测等），有有效期与资质要求。
- **两装两试**：试车不合格后的"再装配—再试车"返工回路。
- **冻结窗口**：周计划前 3 天锁定期（原则上不调整）。
- **齐套九要素**：工装/主材/辅材/刀具/工艺路线/人员资质/WIP 质量状态/设备状态/设备能力。
- **4M**：机 Machine / 人 Man / 料 Material / 法 Method 四个维度可插拔数据组件。
- **MVDS**：最小可行数据模型（L0 门禁的数据基座）。
- **采纳率**：排产方案经计划员确认后可直接下达、无需结构性修改的占比。
